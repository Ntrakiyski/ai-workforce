# Operations, models and agents

Source baseline OWUI-OPS-001 and OWUI-AGENTS-001. The routes and data shapes below are VERIFIED_SOURCE for Open WebUI v0.13.4. The procedures and fixtures are proposed checks for the actual instance.

## Diagnose from the user's perspective

1. Read `GET /api/version` and record the version. `GET /health` is process liveness. `GET /ready` checks startup, database and configured Redis connectivity. Healthy responses from both leave provider and model execution untested. [Health and readiness](https://github.com/open-webui/open-webui/blob/0666e59d26a4d056e0bacee41742486badd71cf8/backend/open_webui/main.py#L3124-L3167)
2. With the intended user's credentials, list `GET /api/models`. Read IDs from `data`. Use the same user for a small, authorized `POST /api/chat/completions` using an ID from that list, a synthetic user message and `stream: false`. Capture the status and whether assistant content arrived. Repeat in the actual UI if streaming, actions or attachments are part of the request. A provider call can incur cost. [Model catalog](https://github.com/open-webui/open-webui/blob/0666e59d26a4d056e0bacee41742486badd71cf8/backend/open_webui/main.py#L874-L943) · [Chat dispatch](https://github.com/open-webui/open-webui/blob/0666e59d26a4d056e0bacee41742486badd71cf8/backend/open_webui/main.py#L1096-L1157)
3. If an admin sees a model and the target user cannot, inspect grants, group membership and enabled status. If both see the ID but inference fails, check provider URL, authentication, the exact upstream model ID and WebUI-to-provider reachability from the WebUI host or container.

## Connect providers and curate models

For an authorized connection change, choose the OpenAI-compatible or Ollama connection editor for the upstream protocol. Check the base URL, its expected path and network namespace. Verify the candidate connection, save the intended configuration, and test a real model as the target user. For API-driven management inspect the deployed verification form and config handlers. The OpenAI config update replaces parallel URL/key lists and indexed options. Preserve their associations on edits, serialize writers, and keep secret-bearing configuration out of logs and reports. [OpenAI config update](https://github.com/open-webui/open-webui/blob/0666e59d26a4d056e0bacee41742486badd71cf8/backend/open_webui/routers/openai.py#L503-L557) · [OpenAI verification](https://github.com/open-webui/open-webui/blob/0666e59d26a4d056e0bacee41742486badd71cf8/backend/open_webui/routers/openai.py#L1020-L1065) · [Ollama verification and settings](https://github.com/open-webui/open-webui/blob/0666e59d26a4d056e0bacee41742486badd71cf8/backend/open_webui/routers/ollama.py#L230-L350)

For a role-specific assistant, create a workspace model based on a working upstream model. Pick a stable new ID, set the system instructions and parameters, then attach only the needed knowledge, tool IDs, actions or filters. Scope access to the intended audience. For automation, inspect `ModelForm` and the target's model router. At this pin, creation uses `POST /api/v1/models/create` and checks the workspace-models permission for non-admin authors. Read back the saved record and exercise the model in a fresh chat. For revisions, capture the current scoped model definition and grants before editing. [Model form](https://github.com/open-webui/open-webui/blob/0666e59d26a4d056e0bacee41742486badd71cf8/backend/open_webui/models/models.py#L250-L269) · [Creation checks](https://github.com/open-webui/open-webui/blob/0666e59d26a4d056e0bacee41742486badd71cf8/backend/open_webui/routers/models.py#L340-L410) · [Model editor serialization](https://github.com/open-webui/open-webui/blob/0666e59d26a4d056e0bacee41742486badd71cf8/src/lib/components/workspace/Models/ModelEditor.svelte#L443-L502)

## Distinguish two agent features

- **Terminal-backed agents.** Select an authorized Open Terminal and working directory. At this pin, `GET /api/models?terminal_id=…` supports terminal model discovery. Discovery reads the terminal's agent catalog and returns available agents with generated `agent:` model IDs. Use the returned ID and selected terminal context when invoking chat. Workspace model forms reject `agent:` IDs as either the saved ID or base model. Control filesystem and command access in the terminal environment. Verify discovery and a harmless read in a dedicated workspace using the target identity. [Terminal model discovery](https://github.com/open-webui/open-webui/blob/0666e59d26a4d056e0bacee41742486badd71cf8/backend/open_webui/utils/agents/discovery.py#L36-L83) · [Chat-side lookup](https://github.com/open-webui/open-webui/blob/0666e59d26a4d056e0bacee41742486badd71cf8/backend/open_webui/main.py#L1123-L1140)
- **Workspace subagents.** For a lead model that should delegate, check the instance subagents setting and the lead model's built-in tool controls. Select the intended child model IDs in its model editor. The editor stores them under `meta.subagents.model_ids`. The runtime intersects them with models visible to the caller. Test an allowed child and a separately restricted child using the same ordinary user. Record the actual delegation result. [Editor controls](https://github.com/open-webui/open-webui/blob/0666e59d26a4d056e0bacee41742486badd71cf8/src/lib/components/workspace/Models/ModelEditor.svelte#L1774-L1813) · [Runtime selection](https://github.com/open-webui/open-webui/blob/0666e59d26a4d056e0bacee41742486badd71cf8/backend/open_webui/utils/subagents.py#L50-L64)

If a capability fails after an edit, restore the scoped prior configuration, confirm its grants and repeat its ordinary-user acceptance check. Report the layer that failed and whether restoration was verified.
