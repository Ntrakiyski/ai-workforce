# Native extensions

Source baseline OWUI-EXT-001, VERIFIED_SOURCE for Open WebUI v0.13.4. The native loader executes the submitted Python and can install declared requirements when loading supplied content. Review the complete module, imports, dependencies and top-level actions before any import into WebUI. Use isolated staging for the first load. Treat Functions and native Tools as backend code with access to the WebUI process. [Function and Tool loaders](https://github.com/open-webui/open-webui/blob/0666e59d26a4d056e0bacee41742486badd71cf8/backend/open_webui/utils/plugin.py#L212-L305)

| Interface | Shape at this pin | Acceptance fixture |
| --- | --- | --- |
| Pipe | A module with a `Pipe` class and `pipe` callable. An enabled Pipe can appear as a model. Select this for a chat backend or custom model behavior. [Pipe discovery and execution](https://github.com/open-webui/open-webui/blob/0666e59d26a4d056e0bacee41742486badd71cf8/backend/open_webui/functions.py#L115-L166) | Select it as the intended user, send one known message, and check its non-streaming and advertised streaming forms. Exercise the provider-down path. |
| Filter | A `Filter` class can define `inlet(body)`, `outlet(body)` or `stream(event)`. Return the appropriate transformed object. Extra injected arguments depend on the handler signature. [Filter dispatch](https://github.com/open-webui/open-webui/blob/0666e59d26a4d056e0bacee41742486badd71cf8/backend/open_webui/utils/filter.py#L134-L205) | Attach to one test model. Send a marker that changes predictably and another that passes through. Check message roles, files, streaming end events and unrelated models. |
| Action | An `Action` class exposes `action(body, …)` for a user interaction on a chat message. Use requested context such as `__user__` and `__event_emitter__` only when needed. [Action dispatch](https://github.com/open-webui/open-webui/blob/0666e59d26a4d056e0bacee41742486badd71cf8/backend/open_webui/utils/actions.py#L76-L117) | Click the control in staging. Verify the intended message and user are affected. For a write, handle duplicate clicks and reject callers lacking permission. |
| Event Function | An `Event` class exposes `event(...)` for backend events. Active Event Functions receive server event payloads. Match the intended event explicitly before doing work. [Event dispatch](https://github.com/open-webui/open-webui/blob/0666e59d26a4d056e0bacee41742486badd71cf8/backend/open_webui/events.py#L1184-L1235) | Trigger the named event and an unrelated event using synthetic records. Check only the intended event resulted in the expected processing. |
| Native Tool | A module with a `Tools` class exposes methods for tool calling. Give callable methods explicit typed parameters, return values and descriptions. Bind the needed tool to a model. [Tool loader](https://github.com/open-webui/open-webui/blob/0666e59d26a4d056e0bacee41742486badd71cf8/backend/open_webui/utils/plugin.py#L212-L250) · [Tool specs and access](https://github.com/open-webui/open-webui/blob/0666e59d26a4d056e0bacee41742486badd71cf8/backend/open_webui/routers/tools.py#L263-L314) | Inspect generated tool specs, invoke a synthetic input through a tool-capable model and confirm execution from the tool result. Check a user outside the share group and an invalid argument. |

Define one extension type per module. Keep business logic independently testable. Scope to a dedicated model or audience when possible. Use the instance's typed valve definitions for operator settings and user valves for supported user preferences. Check whether a Function is global before enabling it. Creation, activation and global toggling are distinct admin operations in this release. Keep the previous source, scoped bindings and activation state for rollback. [Function admin routes](https://github.com/open-webui/open-webui/blob/0666e59d26a4d056e0bacee41742486badd71cf8/backend/open_webui/routers/functions.py#L197-L207) · [Enable/global controls](https://github.com/open-webui/open-webui/blob/0666e59d26a4d056e0bacee41742486badd71cf8/backend/open_webui/routers/functions.py#L279-L361)

The repository's `examples/openwebui-native/` contains local examples. Local calls to Python methods verify their own behavior. Staging verifies discovery, activation, saved settings, caller permissions and actual framework invocation.
